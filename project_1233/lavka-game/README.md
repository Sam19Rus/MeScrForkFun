# «Лавка 2.0: Аукцион» — vertical slice (React + Vite + TypeScript)

Визуальный вертикальный срез игры для Яндекс Игр: **город → цель → аукцион с живыми NPC →
вскрытие лота → верстак (дефекты и реставрация с запчастями) → оценка → решение
(заказ / покупатель / продажа / полка лавки / витрина / фикстура / разборка на запчасти) → итоги дня.**

Экономика, телеметрия, NPC-архетипы, заказы, наборы, лавка и FTUE перенесены из функционального
прототипа `../lavka2-vp` (который остаётся живым резервом и донором логики). Все числа баланса —
в data-файлах (`src/game/data/`), в коде сцен их нет.

## v0.8.0-camera — ГОРОД: ПОЛНАЯ ПЕРЕРАБОТКА РАКУРСА (elevated 3/4 perspective)

Ракурс v0.7 («фронтальная диорама») заменён на **приподнятую 3/4-камеру над районом**:
вся сцена построена на плоскости земли `(wx, wy)` с перспективной проекцией
(`src/art/city/proj.tsx`: `d=F/(F+wy)`, гиперболическое сжатие к горизонту, небо ≈17% кадра).
Улицы идут в глубину и расходятся диагоналями (главная улица, переулки к камере, северная
улица, площадь-поверхность с фонтаном); здания — объёмы с видимыми крышами (плоская с
парапетом / вальма / щипец с коньком), повёрнуты под разными углами; дворы, сады, гаражный
двор и бельевые верёвки дают отрицательное пространство. География запоминается:
лавка у площади → аукцион через дорогу → мастерская за рынком → усадьба на западе.
Прохожие и машины движутся по траекториям A→B в координатах поверхности: масштаб и слой
по глубине, ориентация left/right/front-¾/back-¾, шаги по скорости, перекрываемость
фонарями/скамейками/машинами (полосы глубины с перестановкой DOM). Арт v0.7 (палитра,
материалы, фасады, персонажи, утварь) перенесён под новый пространственный язык, а не
перерисован с нуля. Портрет — отдельная композиция «камера вдоль улицы». Gameplay не тронут.
Отчёт и QA-кадры (10 + сравнение старый/новый ракурс): CITY-PERSPECTIVE-REPORT.md.

## v0.7.0-city — ГОРОД: диорама «маленький живой район» (полная переработка карты) «маленький живой район» (полная переработка карты)

Город переписан с нуля как многослойная 2.5D-диорама (`src/art/city/`: kit.tsx — примитивы
(объёмные коробки зданий с косой проекцией, тени, окна/двери/вывески, транспорт, утварь),

Слои: небо и дальний город с ориентирами (водонапорная башня, часовая башня, фабрика) →
верхняя улица и дальний ряд → средний ряд с дворами → рыночная площадь с фонтаном и лотками →

CITY-VISUAL-QUALITY-REPORT.md.

## Запуск

```bash
npm install
npm run dev        # дев-сервер (обычно http://localhost:5173)
npm run build      # production-сборка в dist/ (статика, base './' — работает с file:// и в ZIP для Яндекс Игр)
npm run preview    # локальный просмотр production-сборки
npm test           # vitest: 52 проверки (логика, реставрация, headless FTUE-день, симуляция бота 3 дня)
```

Режимы URL: `?dev=1` — dev-панель (метрики + IMS + CSV + читы); `?speed=fast` — ускоренные торги;
можно вместе: `index.html?dev=1&speed=fast`.

Визуальный смоук в реальном Chromium (нужен puppeteer и запущенный `npm run preview`):

```bash
NODE_PATH=/tmp/pptr/node_modules node tools/browser-smoke.cjs   # скриншоты → screenshots/
```

## Архитектура

```
src/

  game/        — вся игровая логика, headless-safe (работает в node без DOM)
    data/      — CONFIG, items (37 предметов), npcs, orders, houses, sets/fixtures,
                 parts (запчасти/дефекты/операции/здания города), raw/*.json (арт-донор из v0.2)
    systems/   — goals, clues, orders, auction, results, restoration (новая), buyers (новая)
    director/  — GameController (FSM дня, действия, телеметрия) + AuctionEngine (живые торги)
    economy.ts telemetry.ts sdk.ts (MockSDK) sfx.ts rng.ts types.ts
  scenes/      — ShopScene/AlbumScene, CityScene/PartsScene, HallScene/BiddingScene/LossScene,
                 UnboxScene/WorkbenchScene/AppraisalScene/DecisionScene/DealScene, Intro/DayResult
  components/  — art (ItemSprite+дефекты, NpcFigure+эмоции, Auctioneer, backdrops),
                 ui (кнопки/модалки/тосты/топбар), minigames (4 мини-игры), dev (DevPanel)
tests/         — logic / restoration / controller (headless FTUE-день) / sim (бот 3 дня) + bot.ts
tools/         — browser-smoke.cjs (puppeteer-прогон со скриншотами)
```

**Принцип:** React отвечает только за композицию и рендер; игровые системы и состояние живут в
`GameController`/системах (чистый TS). Аукционный движок — async-цикл, публикующий `AuctionView`
(цены, эмоции NPC, пузыри реплик); постоянно анимируемые объекты — CSS-трансформации SVG-групп,
не отдельные React-компоненты на кадр.

## Ключевые системы вертикального среза

- **Живой аукцион:** 4 NPC-архетипа (Аркадий/Зинаида/Пётр/Нина) сидят в зале, поднимают руку на
  ставке, злятся, когда их перебивают, радуются победе, пасуют с репликами; ведущий бьёт молотком;
  табло цены с pop-анимацией; силуэт игрока с табличкой.
- **Город:** 5 зданий (лавка, склад, усадьба, гараж, запчасти «У Шпуля»); замки по уровню лавки;
  прохожие, облака, дым, голуби; на мобильном карта панорамируется свайпом.
- **Физическая лавка:** интерьер, полки с купленными предметами, фикстуры (радиола/ходики/швейная
  машина/часы) на своих местах, витрина, доска заказов-«пиннов», покупатель дня у прилавка.
- **Детальные предметы и реставрация:** экземпляр лота получает дефекты (грязь/пыль/ржавчина/
  царапины/потёртости/трещины/сломанный механизм/нет детали/расходник/расстройка) по редкости и
  состоянию; каждый дефект виден на предмете (SVG-оверлей) и решается операцией (мини-игра или
  быстрое действие), часть операций требует запчасти. Качество → старая формула v4
  (progress ≥60% веса → q, цена ×(0.6+0.6q)). «Продать как есть» (×0.6), «быстро обтереть» для
  хлама (q=0.75), авто-реставрация за rewarded. Реставрация — решение, а не налог: часть предметов
  выгодно продавать грязными, часть оживает только после полной переборки.
- **Вторая экономика (запчасти):** 4 базовых детали + 4 особые (ручка настройки, пассик, маятник,
  объектив). Источники: магазин (ассортимент дня), лоты-доноры (сломанный приёмник → ручка),
  разборка. Цепочка «заказ → радиоприёмник без ручки → донор на следующем аукционе → ручка →
  реставрация → заказ закрыт» воспроизводится в игре.
- **NPC-покупатели:** раз в день один из архетипов заходит в лавку и делает оффер сверх/ниже рынка
  за «свою» категорию (Пётр ×1.25 за часы, Нина ×1.5 за хлам) — «продать именно ему».
- **Показательные предметы A–G:** крынка (A дёшево-обтереть-продать), радиоприёмник «Меридиан»
  (B редкая деталь), катушечный магнитофон (C тяжёлый, только полная реставрация), золотые часы
  (D интерес Петра), проигрыватель (E набор), фотоальбом (F заказ ×3.0), сломанный приёмник и
  коробка железа (G доноры деталей).

## Телеметрия и dev-режим

События прототипа сохранены (auction_started … next_auction_started, estimate_*, npc_pass,
decision(motivation), day_end, dividend, bailout, ftue_step, ad_*) + новые: op_completed,
restore_strategy, part_bought, donor_disassembled, screen_workbench, engine_error.
Dev-панель: метрики (winRate, маржа, точность оценок, **Item Motivation Score**, стратегии
реставрации, траты на запчасти), CSV-экспорт, читы (+монеты, +запчасти, выдать предмет, открыть
все здания, день+1, завершить реставрацию, форс конкретного аукциона/лота), скорость, сброс.

## Сохранения

localStorage, ключ `lavka_game_save_v3` (save v3; v2 из старого прототипа мигрируется).
Незавершённый лот (верстак/оценка/решение) переживает перезагрузку страницы (п.1.9 требований
Яндекс Игр). MockSDK готов к замене на YandexSDK в MVP-B (те же сигнатуры).

## Известные ограничения

- Арт — стилизованный SVG, созданный кодом (финальный стиль ждёт A/B, как и в прототипе).
- Реклама — mock (логи точек без реальных показов); облачные сохранения — в MVP-B.
- Прохожие/«жизнь города» — минимальный набор; время суток и события — backlog.
- Только RU-локаль.

### v0.5.1-vs (фикс UI/геймплея после пользовательского плейтеста)
- **БАГ «не смог отчистить предмет» (исправлен).** В мини-играх «Очистка/Полировка» грязь
  рисовалась на весь canvas 480×480, а порог «Готово» (≥60%) считался от всей площади:
  оттерев предмет (≈50% площади), игрок физически не мог активировать кнопку. Теперь грязь
  живёт только в зоне предмета, sampler меряет чистоту только этой зоны; кисть крупнее и
  «злее», штрих интерполируется между pointer-событиями (быстрые свайпы не оставляют дыр);
  шкала «Отмыто: X%» с меткой порога 60% вместо скрытого прогресса. Экономика (minProgress
  0.60, qFrom/qTo) НЕ тронута. Воспроизведение/проверка: tools/repro-erase-human.cjs
  (до фикса: 55% и кнопка мертва; после: 90% и активна).
- **БАГ «верстак пустой» (исправлен).** Контент верстака (карточки дефектов, операции,
  нижние кнопки) рисовался ПОД SVG-интерьером: flex-элементы без position/z-index против
  absolutely-positioned фона. Добавлены z-index .wb-layout/.wb-bottom — карточки и кнопки
  видны и кликабельны (раньше smoke-бот жал startOp() через JS и не замечал этого).
- **БАГ «Настройка недоступна никогда» (исправлен).** Блокировка calibrate проверяла
  `requiresOp === 'repair'`, что всегда истина для самого дефекта calibration → операция
  «Настроить» была перманентно залочена. Теперь блокируется, только пока есть нерешённый
  дефект с операцией repair (broken_mech/consumable). Регрессионный тест добавлен.
- **Перекрытия UI:** dev-панель по умолчанию свёрнута (открытая перекрывала кнопки операций
  в правой колонке верстака при плейтесте с ?dev=1); кнопка DEV убрана с кнопки звука
  (top: 8→56px); заголовки сцен на мобильном получили отступ под кнопку DEV; бейджи лотов
