# «Лавка древностей» — вертикальный прототип (MVP-A)

Проверяет **только core loop**: лот → открытие → неожиданная находка → реставрация → оценка → продажа/коллекция → следующий лот.
Спецификация и контекст: `../lavka-validation-preproduction.md` (Приложение A). Экономика: `../validation/economy_sim_v4.py`.

## Как запустить (ноль зависимостей)

1. Открыть `index.html` двойным кликом (работает с `file://` — данные инлайновые, fetch не используется), **или**
2. `npx serve .` → http://localhost:3000

Режимы (query-параметры):
- `index.html` — обычный прогон (FTUE из 3 скриптованных лотов → свободная игра);
- `index.html?gate0` — **Gate 0**: standalone-мини-игра реставрации в цикле (проверка «фанa» без экономики);
- `index.html?dev=1` — dev-панель: счётчики (ящики/продажи/коллекция/дубли/RV/interstitial/bailout), CSV-экспорт телеметрии, сброс сейва, mute.

Тесты:
- `tests/economy-tests.html` — открыть в браузере: χ²-проверка дропа, EV, границы качества/цены, целостность каталога (17 тестов);
- `tests/smoke_game.js` — headless-прогон всего цикла через jsdom: `npm i jsdom` → `NODE_PATH=<путь_к_node_modules> node tests/smoke_game.js` (23 проверки).

## Структура

```
index.html            # загрузчик (порядок скриптов = зависимости)
css/style.css         # тема «сепия», крупные цели ≥48px (аудитория 45+)
js/data.js            # CONFIG (экономика v4 из симуляции) + ITEMS (19 предметов: SVG + истории)
js/economy.js         # единственная точка экономических решений (дроп, EV, качество→цена)
js/telemetry.js       # event-bus, ring-buffer 5000, CSV-экспорт, учёт сессии
js/sdk.js             # ISDK + MockSDK (в MVP-B заменяется на YandexSDK без переписывания сцен)
js/sfx.js             # WebAudio-синтез, без файлов
js/game.js            # FSM + сцены (INTRO/AUCTION/OPENING/RESTORE/APPRAISAL/DECISION/RESULT/ALBUM)
js/main.js            # bootstrap, ?dev, ?gate0
tests/                # экономические тесты + headless smoke
```

## Что заглушено (по спеке A.10)

Реклама — MockSDK (логи вызовов в телеметрии: точки RV «авто-реставрация», interstitial «каждый 3-й переход на аукцион»); апгрейды/лавка, daily/стрик, лидерборды, осколки/звёзды, T2/T3, EN, облачные сохранения (localStorage), звук — синтез. Дубликат = автопродажа 40%. Анти-тупик «bailout» (+160 монет при <130) — временный, телеметрируется (`bailout` — индикатор дефицита экономики; в MVP-B заменяется daily-слоем).

## Что НЕ делать до Gate 1 (по спеке A.11)

Звёзды/осколки, торги, музей, заказы, события, IAP, облако, sticky, A/B иконок, каталог >20, вторая мини-игра, промо.

## Протокол плейтеста (для Gate 1)

1. **Рекрутинг:** 10–15 человек 35–60 лет (знакомые + сообщества барахольщиков/Авито; вознаграждение ~500 ₽).
2. **Формат:** дать ссылку/файл **без объяснений** (проверяем «понятно без инструкций»). Просить играть вслух 8–12 минут. Не подсказывать.
3. **Наблюдать:** где зависают; пропускают ли реставрацию (в `?dev=1` виден `restore_skips`); жмут ли «Продать»/«Оставить» осознанно; читают ли истории находок.
4. **После сессии — 5 вопросов:** (1) Что запомнилось? (2) Хотелось ли открыть ещё ящик — почему? (3) Реставрация: приятно/надоело? (4) Решение «продать/оставить» — чем руководствовались? (5) Что добавить/убрать?
5. **Телеметрия:** в конце попросить нажать «CSV экспорт» (dev-панель) и прислать файл.
6. **Критерии Gate 1** (валид-док, раздел 17): H1 ≥7/12 открывают ≥3 циклов добровольно; H2 авто-скип <40%; H4 keep-rate среди rare+ в диапазоне 20–80% и мотив verbalizable.

## Миграция в MVP-B

Границы модулей соответствуют спеке A.3 (Vite+TS): `data.js → data/config.json + data/items.json`, `sdk.js MockSDK → YandexSDK` (те же сигнатуры: ready/rewarded/interstitial/save/load/leaderboardSubmit/requestReview), `game.js` разбивается на `scenes/*`. Экономические константы уже изолированы в CONFIG — баланс правится без кода.

## Известные ограничения прототипа

- SVG-арт плейсхолдерный (геометрические силуэты) — на Gate 1 проверяем **механику и эмоции цикла**, финальный арт-стиль — отдельная задача (H10: пайплайн ≤40 мин/предмет).
- Одна мини-игра («Очистка»); «Сборка» — в MVP-B.
- Рандом лотов не сидируется между перезаходами (аукцион дня — в MVP-B).
- `bailout` искажает чистоту экономики — его частота в CSV как раз и есть метрика «дефицитности» (симуляция v4 предсказывает ~0 для light-профиля).
