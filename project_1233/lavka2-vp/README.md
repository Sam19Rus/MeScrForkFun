# «Лавка 2.0: Аукцион» — playable-прототип

Полноценный вертикальный срез: **утро лавки → выбор аукциона → осмотр лотов с уликами → оценка → торги с 4 NPC-архетипами → вскрытие → реставрация (3 мини-игры) → решение: заказ/продажа/коллекция/фикстура/витрина → итоги дня → новый день.**

Дизайн-обоснования (почему игрок борется за конкретный лот): `../lavka2-design-value-system.md`.

## Запуск (ноль зависимостей)

Откройте `index.html` двойным кликом в браузере (работает с file://, интернет не нужен).
Режимы: `index.html?dev=1` — dev-панель (метрики + CSV-экспорт); `?speed=fast` — ускоренные торги (для тестов); можно вместе: `?dev=1&speed=fast`.

## Тесты

- `node tests/logic_tests.js` — 27 проверок данных/экономики/NPC/целей (без зависимостей).
- `npm i jsdom && node tests/smoke_game.js` — headless-прогон полного FTUE-дня (30+ проверок).

## Состав

```
js/data.js       — CONFIG, 35 предметов (SVG+истории+улики), 3 сета, 4 фикстуры,
                   4 NPC-архетипа, 10 шаблонов заказов, 3 аукционных дома, FTUE-скрипт
js/economy.js    — оценка (улики→диапазон→полосы), кэпы NPC, цены/шаги торгов, выплаты
js/systems.js    — AuctionSystem, NPCBidderSystem, ClueSystem, OrdersSystem,
                   GoalsSystem (сеты/лавка/витрина), PostAuctionResultSystem
js/restore.js    — мини-игры: очистка, полировка, сборка черепков
js/game.js       — сцены и FSM дня, движок торгов (async), FTUE
js/sdk.js        — MockSDK (реклама-заглушки с логом точек)
js/telemetry.js  — события + CSV-экспорт (спецификация — раздел 10 дизайн-дока)
js/main.js       — boot, dev-панель, ?speed=fast
```

## Протокол плейтеста (Gate-1 для версии 2.0)

Панель: 10–12 человек 25–60 (желательно не-геймеры). Сессия 15–20 минут (2–3 игровых дня), без объяснений.
Вопросы после сессии:
1. Почему вы боролись именно за этот лот? (слушать: заказ/набор/выгода — любой из трёх = успех)
2. Кто из соперников переплачивает и за что? (узнаваемость NPC)
3. Проигрыш аукциона: что вы узнали? (обучение вместо фрустрации)
4. Хотелось ли начать следующий день? Почему?
5. Что непонятно в оценке лота до торгов?
Из dev-панели забрать CSV и выписать: точность оценок (день 1 vs день 3), долю мотивированных побед, длину дня.
Критерии — таблица в разделе 11 дизайн-документа.

## Известные ограничения прототипа

- Арт плейсхолдерный (геометрические SVG); финальный стиль — после гейта.
- Только RU; облачные сохранения и реальная реклама — в MVP-B (SDK-обёртка готова к замене).
- Баланс NPC-кэпов и маржи — первый проход; калибруется по CSV плейтестов (параметры в data.js CONFIG).
- `bailout` (+150 ₽ при <120) — временный анти-тупик, телеметрируется.
