# ОТЧЁТ: «Лавка» — переход от прототипа v3 к визуальному вертикальному срезу

**Дата:** 23.09.2026. **Результат:** новый проект `lavka-game/` (React + Vite + TypeScript) —
играбельный вертикальный срез; старый прототип `lavka2-vp/` не тронут и остаётся резервом/эталоном логики.
**Проверено:** 51/51 unit+headless-тест (10 прогонов подряд стабильно), production-сборка, полный
прогон в реальном Chromium (puppeteer, 25 скриншотов, 0 ошибок консоли) на desktop 1280×800 и mobile 390×844.

---

## 1. Что изменено

1. **Стек:** vanilla JS + глобальные `window.*` → React 19 + Vite 7 + TypeScript (strict),
   модули с явными импортами, production-сборка `dist/` (132 КБ gzip, base `./` — готово к ZIP для Яндекс Игр).
2. **Архитектура:** геймплей вынесен из UI. `GameController` (FSM дня, действия, телеметрия) и
   `AuctionEngine` (async-движок торгов) — чистый TS, headless-safe; React-компоненты только
   рендерят снапшот (`useSyncExternalStore`) и вызывают действия. Постоянно анимируемые объекты —
   CSS-трансформации SVG-групп, не React-компонент на каждый кадр.
3. **Визуальный слой (новое):** город-карта с 5 зданиями и «жизнью»; интерьер лавки с полками,
   витриной, фикстурами, доской заказов, покупателем дня; аукционный зал (сцена, софит, ведущий с
   молотком, ряд NPC); живые NPC-фигуры с эмоциями и репликами; вскрытие упаковки с лучами и пылью;
   верстак (стена инструментов, лампа, тиски); магазин запчастей «У Шпуля»; до/после на оценке.
4. **Предметы стали детальнее:** экземпляр лота теперь несёт список дефектов (10 типов), видимых
   прямо на арте (SVG-оверлеи: грязь, пыль, ржавчина, царапины, потёртости, трещина, сломанный
   механизм, отсутствующая деталь «?», расходник, расстройка).
5. **Реставрация пересобрана** из «одной мини-игры» в систему операций (см. §3).
6. **Сохранения:** save v3 (запчасти, покупатель дня, pending-лот); v2 мигрируется автоматически;
   незавершённый предмет переживает перезагрузку (п.1.9).

## 3. Какие новые системы добавлены

1. **Дефекты экземпляров** (`systems/restoration.ts`, `data/parts.ts`): пул по категории, число по
   редкости (junk 1 … legend 3–5), коррекция по состоянию (cond<0.85 → +1), heavy-bias, forced для
   FTUE; каждый дефект = операция + вес + стоимость запчастями.
2. **Качество через прогресс решения дефектов:** p = Σ(вес×качество операции)/Σвесов → та же
   формула v4 `qualityFromProgress` (клиф 55%/97%). «Продать как есть» = q0 (×0.6); частичная
   реставрация ниже 60% веса не даёт бонуса — осмысленный выбор «не чинить наполовину».
3. **Операции реставрации (6):** очистка, полировка (обе — canvas-стирание), сборка (мозаика),
   ремонт и замена детали (интерактив «открути-поставь» с расходом запчастей), калибровка
   (тайминг-мини-игра «поймай стрелку», блокируется до ремонта механизма).
4. **Запчасти (8):** универсальные/электронные/механические/полироль + 4 особые (ручка настройки,
   пассик, маятник, объектив). Магазин «У Шпуля» (базовые всегда, особые — ассортимент дня по сиду),
   лоты-доноры, разборка донора на верстаке решения.
5. **NPC-покупатели в лавке:** детерминированный «покупатель дня», оффер сверх/ниже рынка за свою
   категорию (Пётр ×1.25 часы, Аркадий ×1.2 техника, Нина ×1.5 хлам, Зинаида ×0.95 всё) — мотивация D.
6. **Город как хаб:** карта, здания с замками по уровню лавки, зум-переход, цель дня из заказов;
   на мобильном — панорамирование свайпом.
7. **Живая сцена торгов:** AuctionView (эмоции idle/think/bid/lead/pass/angry/happy/sad, пузыри
   реплик из данных NPC, рука вверх на ставке, реакции на ставку игрока, молоток ведущего).
8. **Показательные предметы A–G** (§1.30 ТЗ): +3 новых предмета (радиоприёмник «Меридиан» с
   отсутствующей ручкой; сломанный приёмник-донор ручки; коробка старого железа) и расширения
   существующих (reel — heavy+belt; camera/binoculars — lens; cuckoo — pendulum).
9. **Dev-панель расширена** (§35): +монеты, +запчасти, выдать предмет, открыть все здания, день+1,
   завершить реставрацию, форс конкретного аукциона И лота, CSV, скорость, сброс, лог последних событий,
   новые метрики (стратегии реставрации, траты на запчасти, разборки).
10. **Инструменты проверки:** vitest-набор (51), headless-бот (`tests/bot.ts`), browser-smoke
    (puppeteer, скриншоты всех сцен, desktop+mobile).

## 4. Что осталось временным / placeholder (честно)

- **Арт** — процедурный SVG «на коленке»: стиль согласован (тёплый ретро), но финальный арт-стиль
  (A/B cozy/industrial) не выбирали; лица NPC — из старого прототипа.
- **Реклама** — MockSDK: rewarded «выдаёт награду» мгновенно, interstitial только логируется.
- **Покупатель дня** — стоит в лавке как ambiance; оффер делается на экране решения, а не «у прилавка».
- **«Жизнь города»** — 2 прохожих, облака, дым, голуби; время суток, события, редкие предложения — backlog.
- **История предмета** — отображается на оценке; механическое влияние истории (доп. улика/интерес
  покупателя) НЕ добавлялось сознательно, чтобы не трогать экономику оценки до плейтеста.
- **Посетители лавки** — только покупатель дня; поток посетителей с витрины (связь «коллекция →
  покупатели») — backlog MVP-B.
- **Разборка любых вещей** — только доноры с `yieldParts`; «разобрать свой хлам с полки» — backlog.
- **Звук** — синтез WebAudio, без музыки/атмосферы зала.

## 5. Ограничения и технический долг

1. **Портретная вёрстка торгов** улучшена (NPC-ряд со скроллом, кнопки на всю ширину), но на
   реальном телефоне не проверялась — только эмуляция 390×844 в Chromium.
2. **Город на мобильном** — панорама со свайпом: рабочая, но не «открытка»; возможен редизайн
   карты под портрет (2 ряда зданий).
3. **Размер бандла 132 КБ gzip** — норма, но 37 SVG-предметов инлайнятся в JS; при росте каталога
   до 60–72 (MVP-B) нужен конвейер (отдельные ассеты/спрайты).
4. **`Math.random` в npcDecide и активации NPC** — как в прототипе: торги не детерминированы
   (важно для симов, но «тест конкретного аукциона» в dev форсит только лот, не ход торгов).
5. **pending-лот** сериализуется вместе с DayCtx — сохранение растёт с числом лотов; для облака
   (≤200 КБ) пока в норме, но нужен контроль.
6. **Авто-реставрация** требует ВСЕ запчасти (иначе отказ) — решение в пользу честности экономики;
   как монетизация сработает — вопрос плейтеста.
7. Старый прототип `lavka2-vp/` и новый `lavka-game/` теперь живут параллельно: правки баланса
   нужно вносить в `lavka-game/src/game/data/` (новый источник истины — `config.ts`).

## 6. Как запустить

```bash
cd lavka-game
npm install
npm run dev                # http://localhost:5173  (играть)
npm run build && npm run preview   # production-сборка
npm test                   # 51 проверка
# визуальный смоук (опционально, нужен puppeteer):
NODE_PATH=/tmp/pptr/node_modules node tools/browser-smoke.cjs
```
Игровые режимы: `?dev=1` (панель метрик и читы), `?speed=fast` (быстрые торги).
Целевой сценарий из ТЗ §39 проходится целиком: лавка → заказ → город → склад → торги (NPC
торгуются, эмоции) → победа → вскрытие → верстак (дефекты, операции, запчасти) → до/после →
решение (заказ/продажа/полка) → итоги → новый день.

## 8. Следующие 3–5 задач (мои рекомендации, по приоритету)

1. **Живой плейтест Gate 1–3 на новой сборке** (панель 10–12 чел. 25–60 лет; протокол в
   `lavka2-vp/README.md` + вопросы по реставрации: «когда реставрация была выгодна?», «зачем
   купили донора?»). До данных продуктовых решений не принимать — правило проекта в силе.
   CSV через `?dev=1`; смотреть IMS, точность оценок, стратегии реставрации, долю as-is.
2. **Проверить связку «деталь → донор → аукцион» на живых игроках** и, если работает, расширить:
   ещё 2–3 особые детали, «предложение детали от NPC» (сейчас backlog), подсветка на осмотре
   «в этом лоте есть нужная вам деталь» (сейчас игрок должен помнить каталог доноров).
3. **Арт-проход A/B** (стиль уже утверждён композиционно): финальные лица NPC, иконка/промо
   (≥70% геймплея), возможно — сгенерированные фоны города/зала в выбранном стиле (п.1.23
   разрешает предгенерированный ИИ-арт).
4. **MVP-B подготовка (после PASS гейтов):** YandexSDK вместо Mock (реклама с gameplayAPI.stop/start,
   облачные сохранения), EN-локаль, каталог 60–72 предмета с конвейером ассетов, сид-аукцион дня.
5. **Портретная полировка на реальном устройстве:** тач-эргономика торгов (кнопка ставки под большим
   пальцем), жесты верстака, время анимаций (сейчас `?speed=fast` для тестов; для игроков, возможно,
   нужна настройка или автопропуск вскрытия).

### Самопроверка «показателя качества» (ТЗ §40)

Если убрать текст и кнопки, остаются: карта города с домами, зал с людьми, которые поднимают руки
и спорят, коробка на столе под софитом, грязный предмет на верстаке, который на глазах становится
чистым, и полка лавки, которая заполняется вашими вещами. Ощущение «я владелец маленькой лавки,
который ищет вещи, торгуется и чинит их» — передаётся; самые слабые места по-прежнему текстовые
(заказы/улики) и финальный арт.
