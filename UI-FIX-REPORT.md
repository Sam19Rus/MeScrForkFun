# Отчёт по проверке UI и корректности «Лавка 2.0: Аукцион» (v0.5.1-vs)

Дата: 2026-09-21. Запрос: «проверь проект на ошибки UI, перекрытия элементов и общую
корректность; я не смог отчистить предмет после получения; пришли архив с исправленным проектом».

Метод: код-ревью + headless-Chromium (puppeteer) с реальными кликами/свайпами по UI,
дампы геометрии элементов (tools/probe-ui.cjs), визуальный разбор 30+ скриншотов
(desktop 1280×800 и mobile 390×844), юнит-тесты, file://-проверка.

## Найденные и исправленные баги

### 1. «Не смог отчистить предмет» — ГЛАВНЫЙ БАГ (подтверждён воспроизведением)
**ФАКТ, причина:** в мини-играх «Очистка/Полировка» (EraseGame) грязь рисовалась на ВЕСЬ
canvas 480×480, а замер чистоты и порог кнопки «Готово» (`minProgress = 60%`, экономика v4)
считались от всей площади canvas. Предмет занимает центральный квадрат 340×340 ≈ 50%
площади → игрок, идеально оттерев предмет, получал ≤~55% и кнопка не активировалась НИКОГДА.
**Воспроизведение:** tools/repro-erase-human.cjs («человеческие» круговые движения по предмету):
ДО фикса — «Готово» неактивна, «Отмыто 55%»; ПОСЛЕ — 89–90%, кнопка активна.
Роботизированный зигзаг smoke-бота тер весь canvas целиком, поэтому автотесты баг не ловили.
**Фикс:** грязь генерируется только в зоне предмета; sampler меряет чистоту только этой зоны
(«отмыл предмет» = «можно финишить»); кисть увеличена (30/34 → 40/44) с «злым» ядром градиента;
штрих интерполируется между pointer-событиями (быстрые свайпы/мышь не оставляют пропусков);
добавлена честная шкала «Отмыто: X%» с меткой порога 60% (раньше игрок видел только
нормированное «качество слоя» и не понимал, почему кнопка мертва).
**Экономика НЕ изменена:** minProgress 0.60 / qFrom 0.55 / qTo 0.97 / формула v4 — как валидировано симуляцией.

### 2. Верстак выглядел пустым (контент под фоном)
**ФАКТ:** карточки дефектов, карточки операций и нижние кнопки («Продать как есть»,
«Идеально», «Готово → Оценить») рисовались ПОД SVG-интерьером верстака: `.wb-layout` и
`.wb-bottom` — flex-элементы без position/z-index, а фон `.shop-bg` — absolutely positioned
(порядок отрисовки CSS). Кнопку операции нельзя было нажать мышью (smoke-бот запускал
`startOp()` через JS и не замечал). **Фикс:** `position: relative; z-index` у `.wb-layout` (3)
и `.wb-bottom` (5). Проверено кликом из UI: кнопка «Отмыть» нажимается.

### 3. «Настройка механизма» была недоступна НИКОГДА
**ФАКТ:** блокировка операции calibrate проверяла `defects.some(d => !d.resolved &&
DEFECTS[d.id].requiresOp === 'repair')`, но `requiresOp: 'repair'` стоит у САМОГО дефекта
`calibration` → при его наличии «Настроить» перманентно залочена («сначала почините механизм»,
когда чинить нечего). Ручная калибровка расстроенного механизма была невозможна
(спасала только авто-реставрация за рекламу). **Фикс:** условие смотрит на нерешённые дефекты
с ОПЕРАЦИЕЙ repair (broken_mech/consumable). Добавлен регрессионный тест
(«калибровка БЕЗ поломки не заблокирована», 52-й тест).

## Проверено и НЕ сломано / корректно

- 52/52 vitest (логика 28, реставрация 21, контроллер 2, сим 1) × стабильно; `tsc --noEmit` чисто.
- browser-smoke: ERRORS(0), 25 скриншотов desktop+mobile (console + pageerror пусты).
- Мини-игры в браузере кликами из UI: очистка (90% «человеческими» движениями), мозаика
  (сборка 9/9), ремонт (3 нажатия), калибровка (3 попытки) — все завершают операцию
  (tools/minigames-check.cjs).
- file:// рендер без ошибок (tools/file-test.cjs) — билд пригоден для ZIP Яндекс Игр.
- Сборка: 132.5 КБ gzip (base './').
- Экономика, телеметрия, сохранения (save v3), FTUE, NPC, заказы/наборы — не тронуты
  (правки только UI/доступность операций + регрессионный тест).

## Что НЕ правил (осознанно)

- Эмоции/реплики NPC, Math.random в npcDecide (недетерминизм торгов) — по прошлому решению,
  ждёт данных плейтеста.
- Тосты перекрывают верх сцен на 2.4 с — штатное поведение уведомлений, не баг.
- «Тofu»-квадраты вместо эмодзи на скриншотах — в headless-контейнере нет emoji-шрифта;
  в реальном браузере эмодзи на месте.
- lavka2-vp (прототип-резерв) содержит ту же ошибку EraseGame — НЕ тронут (он резерв/эталон
  логики, не deliverable); при возврате к нему учесть фикс.

## Как запустить и проверить

```bash
cd lavka-game
npm install && npm run build && npm run preview        # http://localhost:4173
npm test                                               # 52/52
NODE_PATH=/tmp/pptr/node_modules node tools/browser-smoke.cjs      # смоук + скриншоты
NODE_PATH=/tmp/pptr/node_modules node tools/repro-erase-human.cjs  # баг №1: «Готово» активна
NODE_PATH=/tmp/pptr/node_modules node tools/minigames-check.cjs    # все 4 мини-игры
NODE_PATH=/tmp/pptr/node_modules node tools/probe-ui.cjs           # геометрия/перекрытия
```
Играть: `index.html?dev=1` (панель теперь открывается кнопкой «DEV»), плейтест Gate 1–3 без изменений.
